# Facebook Page Reaction Abuse Monitoring and Moderation Automation

**العنوان العربي:** أتمتة مراقبة إساءة استخدام تفاعلات صفحات فيسبوك وإدارتها

**الاسم المختصر:** نظام دفاع ضد إساءة استخدام تفاعلات الغضب والضحك في صفحات فيسبوك

**الدور:** مهندس الأتمتة، المطوّر، ومسؤول التشغيل

**الحالة:** عرض عام منزوع البيانات الخاصة لنظام بنيته ونشرته وشغّلته؛ ولا أدّعي أن تشغيله الأصلي ما زال نشطاً الآن.

> حدّدت المشكلة التشغيلية، وصممت منطق المراقبة والإدارة، وبنيت الأتمتة وتكامل فيسبوك، وهيأت تشغيلها، ونشرتها، واستخدمتها لحماية الصفحات التي كنت مسؤولاً عنها.

## المشكلة التي عالجتها

تعرّضت صفحات فيسبوك كنت أديرها لحسابات تضيف بصورة منسقة تفاعلات الغضب والضحك إلى المنشورات والتعليقات. كان هذا النمط قادراً على تشويه الانطباع العام لدى العملاء، بينما كانت متابعة كل منشور وتعليق وتفاعل وحساب يدوياً بطيئة ومعرّضة لتكرار العمل أو تأخره.

بنيت نظام مراقبة وأتمتة لاكتشاف إساءة استخدام التفاعلات والاستجابة لها. كان هدفي إنشاء مسار تشغيلي مستمر يحدد الحسابات ذات الصلة، ويمنع تكرار الإجراء على الحساب نفسه، ويتأكد من هوية الصفحة المنفذة، ويحفظ حالة كافية لاستكمال العمل بصورة منضبطة.

## ما الذي بنيته

ينفذ النظام المسار التالي:

```text
تشغيل مجدول
  -> اكتشاف منشورات الصفحة وتعليقاتها وتقييماتها الاختيارية عبر Graph
  -> قراءة متصفح تفاعلات كل عنصر عبر جلسة Facebook مصرح بها
  -> مطابقة تسميات ANGRY وHAHA وعلامات مصادر أيقوناتها وروابط الحسابات الرقمية
  -> منع تكرار الحسابات والإجراءات في حالة JSON ذرية
  -> إدراج إجراء إداري على مستوى الصفحة
  -> تشغيل وضع --apply صراحة
  -> التبديل إلى هوية الصفحة الأصلية عبر Playwright
  -> إرسال إجراء الحظر على مستوى الصفحة أو التوقف الآمن
  -> تسجيل الحالة وإرسال تنبيه Telegram اختيارياً
```

الوضع الافتراضي هو الرصد فقط. يجري المتصفح قراءات مصرحاً بها ومحدودة ويسجل الحالة محلياً، لكنه لا يغيّر حالة فيسبوك. لا يحاول النظام تنفيذ إجراء إداري قبل استخدام مسار التنفيذ الصريح. وعند التنفيذ، يجب أن يتحقق المتصفح من هوية الصفحة التي جاء منها الحدث؛ وإلا يتوقف الإجراء.

## منطق المراقبة والقرار

جعلت أنواع التفاعل قابلة للضبط، مع دعم `ANGRY` و`HAHA` كإشارات لإساءة الاستخدام. يكتشف Graph منشورات الصفحة وتعليقاتها الاختيارية وتقييماتها، لكنه لا يعدد تفاعلات المستخدمين الآخرين. يفتح Playwright متصفح التفاعلات الموثق لكل عنصر، ولا يقبل الحساب إلا عند تطابق التسمية الظاهرة وعلامة مصدر أيقونتها، وبعد التحقق من رابط الحساب الرقمي.

لكل حساب مطابق، ينشئ النظام سجلاً محلياً أو يعيد استخدامه، ثم يتحقق مما إذا كان الإجراء نفسه قد أُدرج أو أُرسل سابقاً ضمن الصفحة ذاتها. يحفظ مستند JSON صارم ومحدد الإصدار هذا التفرد، ويحميه قفل POSIX وتحديث باستبدال ذري.

تقييمات الصفحة لها مسار منفصل. يمكن لمطابقة الكلمات العربية المضبوطة أن ترسل تنبيهاً، لكنها لا تنشئ إجراء حظر على حساب. بذلك يبقى تنبيه المحتوى منفصلاً عن قرار إداري على مستوى الحساب.

## مسار الإجراء الإداري

يستخدم منفذ الإجراءات Playwright لأن الحظر على مستوى الصفحة يُنفذ من خلال واجهة فيسبوك. قبل الوصول إلى أداة الإجراء، يختار الصفحة التي نشأ منها الحدث ويتحقق من هويتها. بعد ذلك فقط ينتقل إلى واجهة الحساب ويحاول إرسال الحظر.

وضعت لهذا الحد حدوداً واضحة:

- يجري الرصد قراءات متصفح فقط من دون أي تغيير إداري؛
- يتطلب التنفيذ تشغيل وضع `--apply` صراحة؛
- يُفحص زوج الحساب والإجراء مقابل الحالة المحلية؛
- يؤدي تعذر تأكيد هوية الصفحة إلى إيقاف الإجراء؛
- تُسجل النتيجة أو حالة الفشل من دون كشف بيانات الدخول؛
- تنبيهات Telegram اختيارية ولا تتحكم في المسار الأساسي.

## البنية

| المكوّن | المسؤولية |
|---|---|
| المجدول / نقطة تشغيل الأوامر | بدء دورة مراقبة واحدة أو مسار التنفيذ الصريح |
| تكامل Facebook Graph | اكتشاف المنشورات والتعليقات الاختيارية والتقييمات |
| جامع Playwright | قراءة متصفح التفاعلات بحدود والتحقق من أزواج التسمية وعلامة مصدر الأيقونة وروابط الحسابات الرقمية |
| قواعد الكشف | اختيار نشاط Angry/Haha المضبوط وتنبيهات كلمات التقييمات |
| حالة JSON ذرية | منع تكرار الحسابات والإجراءات الخاصة بكل صفحة وتسجيل الحالة |
| منفذ Playwright | تنفيذ الحظر تحت الصفحة الأصلية في وضع apply فقط |
| تكامل Telegram الاختياري | إرسال تنبيهات تشغيلية من دون التحكم في سير العمل |

تأتي رموز الصفحات وبيانات التنبيه من متغيرات البيئة. لا يحتوي المستودع العام على رموز الوصول أو جلسات المتصفح أو معرّفات الصفحات والحسابات أو الروابط أو سجلات التشغيل الأصلية؛ ويستخدم أمثلة ومعرّفات اصطناعية فقط.

## الاعتمادية ومعالجة الفشل

أضع حداً لكل مسار Graph وأقسم سقف طلباته بين الصفحات. أقسم أيضاً `MAX_REACTION_BROWSER_PAGES_PER_CYCLE` بينها، وأحد عدد الحسابات لكل عنصر. قد يؤجل الترتيب الثابت والمحدود محتوى لاحقاً إذا استهلكت العناصر الأولى السقف. يحد `MAX_MODERATION_ACTIONS_PER_RUN` كل دورة تنفيذ، ويمنع قفل POSIX تعارض تحديثات الحالة.

تبقى أخطاء المتصفح السابقة لنقرة التأكيد في حالة `failed`، ولا تعود إلى الانتظار إلا بأمر إعادة المحاولة الصريح. أما حالات `applying` المتوقفة و`uncertain` غير المحسومة فتحتاج إلى مطابقة الحالة مع الصفحة قبل تسجيلها كمرسلة أو إعادتها للطابور. لا أدّعي تنفيذًا ذرياً لمرة واحدة عبر النظام المحلي وفيسبوك.

## الأمان والبيانات الخاصة

أمرر بيانات صفحات فيسبوك وTelegram عبر تهيئة بيئية خاصة. تنتقل رموز Graph داخل Bearer headers، وتبقى حالة المتصفح وحالة JSON وملف القفل والسجلات والنسخ الاحتياطية خارج التحكم في الإصدارات وبصلاحيات مقيدة. يتحقق النظام من البيانات والمعرّفات والروابط والتسميات وحالة الواجهة عند حدودها. قبل كل إجراء، يعيد Playwright التحقق من الصفحة ويتوقف إذا تعذر إثبات الصفحة أو رابط الحساب الرقمي.

## التقنيات

Python 3.11+، مكتبة Python القياسية للاتصال وJSON والملفات، Facebook Graph API، Playwright مع Firefox، تنبيهات Telegram الاختيارية، وجدولة وقفل POSIX.

## اختياراتي التشغيلية

- **منع التكرار:** تمنع مفاتيح الحساب والإجراء الدائمة تكرار العمل المحلي بين دورات الاستطلاع.
- **تنفيذ مضبوط:** يظل الرصد مفيداً من دون تمكين الإجراء الإداري في المتصفح.
- **هوية صحيحة:** تدخل الصفحة الأصلية ضمن حد التنفيذ، ويؤدي عدم اليقين إلى التوقف الآمن.
- **اعتماديات محدودة:** يستخدم النظام حالة JSON من المكتبة القياسية مع Graph وPlaywright وTelegram الاختياري من دون طبقة خدمات لا يحتاجها المسار.
- **تهيئة خاصة:** تبقى بيانات الدخول وحالة المتصفح خارج نظام التحكم في الإصدارات.

## القيود الحالية

لا تدعم وثائق Meta الحالية تعداد تفاعلات المستخدمين الآخرين عبر Graph لهذا المسار. لذلك يحتاج رابط متصفح التفاعلات في mbasic والتسميات الظاهرة وعلامات مصادر الأيقونات ونص جلب المزيد والمحددات وتوافق عناصر التعليقات وروابط الحسابات الرقمية إلى تحقق حي مصرح به. وقد تتغير أيضاً حقول Graph وصلاحياته وإصداراته وقواعد الوصول إلى الصفحات. لا تثبت الاختبارات العامة التوافق الحي الحالي.

العرض العام منزوع البيانات الخاصة ويعمل ببيانات اصطناعية. وهو يوضح مسار المراقبة والكشف ومنع التكرار والتأكيد وتسجيل الحالة من دون ادعاء تشغيل حي حالي أو عدد إجراءات أكدته المنصة.
